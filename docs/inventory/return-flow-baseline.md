# 退貨流程基準線

本基準線定義銷售退貨與進貨退貨。退貨不是刪除原銷售或原採購，而是建立新的退貨單據，並透過 `sourceDocumentNo` 關聯原單，讓庫存、應收應付、毛利、發票與報表都能追溯。

## 核心原則

- 退貨必須建立退貨單，不改寫原單。
- 銷售退貨與進貨退貨都需記錄原因、日期、操作者與原單。
- 退貨數量不可超過原單可退數量。
- 退貨會影響庫存與帳款，但不應直接刪除收入或成本歷史。
- 退貨與作廢不同；作廢處理錯誤單據，退貨處理已成立交易的後續反向營運事件。

## 單據類型

| 單據 | 前綴 | 說明 |
|---|---|---|
| 銷售退貨 | `SRTN` | 客戶退回商品，可能增加可售庫存或進入待驗區。 |
| 進貨退貨 | `PRTN` | 退回商品給供應商，扣減庫存並調整應付或建立應收折讓。 |

## 銷售退貨流程

1. 選擇原銷售單 `SO`。
2. 選擇退貨商品與數量。
3. 記錄退貨原因。
4. 選擇退回位置：可售庫存、待驗區或報廢。
5. 建立 `SRTN-{YYYYMM}-{SEQUENCE}`。
6. 依退回位置產生庫存事件。
7. 調整應收、收款或建立退款待辦。
8. 報表顯示原銷售、退貨與淨銷售。

## 進貨退貨流程

1. 選擇原採購單 `PO`。
2. 選擇退貨商品與數量。
3. 記錄退貨原因。
4. 系統檢查可退庫存是否足夠。
5. 建立 `PRTN-{YYYYMM}-{SEQUENCE}`。
6. 扣減庫存。
7. 調整應付、付款或建立供應商退款待辦。
8. 報表顯示原採購、退貨與淨採購。

## 必要欄位

| 欄位 | 說明 |
|---|---|
| `documentNo` | 退貨單號。 |
| `sourceDocumentNo` | 原銷售或原採購單號。 |
| `documentType` | `salesReturn` 或 `purchaseReturn`。 |
| `productId` | 商品。 |
| `warehouseId` | 影響倉庫。 |
| `quantity` | 退貨數量。 |
| `reason` | 退貨原因。 |
| `inspectionStatus` | 待驗、可售、報廢。 |
| `createdBy` | 建立者。 |
| `confirmedBy` | 確認者。 |
| `relatedDocumentNos` | 原單、帳款、退款或發票關聯。 |

## 財務與報表

- 銷售退貨應減少淨銷售與毛利。
- 進貨退貨應減少淨採購與庫存成本。
- 若原單已收款，退貨需建立退款或折讓待辦。
- 若原單已付款，進貨退貨需建立供應商退款或應付折讓。
- 報表需可看原始金額、退貨金額與淨額。

## 與其他基準線的關係

- 退貨單號遵守單據編號規則。
- 退貨確認與作廢遵守審核流程與資料生命週期。
- 發票折讓與稅務處理遵守發票、稅務、會計分錄基準線。
- 退回待驗區時遵守借出歸還與待驗庫存概念。
