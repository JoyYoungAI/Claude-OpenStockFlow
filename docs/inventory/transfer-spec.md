# 調撥規格

調撥是延伸模組 `E1`，用來處理同一商品在不同倉庫之間的庫存移動。調撥不代表採購、不代表銷售，也不應產生收入、成本或應收應付；它只改變庫存所在位置。

## 模組定位

| 項目 | 定義 |
|---|---|
| UI 按鈕 | `E1 調撥` |
| data-tab | `transfers` |
| data-view | `transfers` |
| 單據前綴 | `TRF` |
| 主要目的 | 同商品跨倉移動，維持總庫存不變 |

調撥屬於延伸模組，不列入第一版主流程編號。它會影響庫存報表與倉庫調撥摘要，但不改變整體商品總庫存。

## 流程

1. 使用者選擇來源倉庫。
2. 使用者選擇目的倉庫。
3. 使用者選擇商品與調撥數量。
4. 系統檢查來源倉庫庫存是否足夠。
5. 系統建立 `TRF-{YYYYMM}-{SEQUENCE}` 調撥單號。
6. 來源倉庫扣減庫存，目的倉庫增加庫存。
7. 調撥紀錄出現在調撥清單、庫存異動與報表中心。

## Transfer

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---:|---|
| id | number | 是 | 調撥紀錄 ID |
| documentNo | string | 是 | 調撥單號，例如 `TRF-202605-001` |
| productId | number | 是 | 商品 ID |
| fromWarehouseId | number | 是 | 來源倉庫 ID |
| toWarehouseId | number | 是 | 目的倉庫 ID |
| quantity | number | 是 | 調撥數量，必須大於 0 |
| date | string | 是 | 日期，格式 `YYYY-MM-DD` |
| note | string | 否 | 備註 |
| status | string | 否 | 單據狀態，需符合資料生命週期基準線 |

若未來支援一張調撥單多商品，`Transfer` 可提升為表頭，並以 `lines` 保存商品明細；但第一階段可先以每筆調撥紀錄代表一個商品明細。

## 資料規則

- 來源倉庫與目的倉庫不可相同。
- 商品必須存在且為可用商品。
- 來源倉庫與目的倉庫必須存在且為可用倉庫。
- 調撥數量必須大於 0。
- 來源倉庫可用庫存不足時，不可建立調撥。
- 調撥不建立應收、應付、收入或付款。
- 已確認且影響庫存的調撥不可直接刪除；需依資料生命週期與作廢基準線作廢或建立反向調撥。

## 庫存影響

調撥會產生兩個方向相反的庫存影響：

| 倉庫 | 影響 |
|---|---|
| 來源倉庫 | 扣減調撥數量 |
| 目的倉庫 | 增加調撥數量 |

整體商品總庫存不變：

```text
商品總庫存 = 各倉庫庫存加總
調撥後商品總庫存 = 調撥前商品總庫存
```

## 報表引用

- 庫存報表需依倉庫顯示調撥後庫存。
- 庫存異動明細需能用 `documentNo` 查到調撥來源與目的。
- 報表中心可顯示各倉庫調入、調出與淨流量。
- 財務摘要不應因調撥產生收入、成本、應收或應付。
- 作廢調撥預設不列入有效庫存異動，但需能查詢作廢紀錄。

## 與共用基準線的關係

- 單據編號遵守 [單據編號與關聯基準線](document-linkage-baseline.md)。
- 作廢、反向調撥與不可直接刪除規則遵守 [資料生命週期與作廢基準線](data-lifecycle-void-baseline.md)。
- 危險操作與 disabled 提示遵守 [操作狀態與風險基準線](operation-risk-baseline.md)。

## 驗證

- 建立調撥後，來源倉庫庫存減少。
- 建立調撥後，目的倉庫庫存增加。
- 同商品總庫存不因調撥改變。
- 來源倉庫庫存不足時，系統拒絕建立調撥。
- 來源倉庫與目的倉庫相同時，系統拒絕建立調撥。
- 調撥單號使用 `TRF-{YYYYMM}-{SEQUENCE}`。
- 庫存異動與倉庫調撥摘要可查到調撥紀錄。
- 調撥不產生應收、應付、收入或付款。
