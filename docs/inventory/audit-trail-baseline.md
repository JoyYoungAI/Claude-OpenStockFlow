# 稽核軌跡基準線

本基準線定義 StockFlow 在新增、刪除、修改、查詢與列印時，必須留下哪些可追溯紀錄。權限控管回答「誰能做」，稽核軌跡回答「誰在何時、以什麼角色、對哪筆資料、做了什麼、原因是什麼、結果如何」。

## 核心原則

- 稽核紀錄不可被一般使用者修改或刪除。
- 高風險操作不得只覆寫原資料，必須留下前後差異。
- 查詢與列印也是操作，不能只記錄寫入行為。
- 已影響庫存、財務、業績或報表的資料，不直接刪除；需作廢、反向事件或保留 tombstone。
- 稽核紀錄需能從原單、反向單、帳款、報表與使用者角色反查。
- 單機版第一階段可寫入 localStorage；多人版必須由服務端寫入並防止前端竄改。

## 稽核事件範圍

| 類型 | action | 說明 |
|---|---|---|
| 新增 | `create` | 新增商品、倉庫、往來對象、單據、收付款、退貨、調撥、盤點。 |
| 刪除 | `delete` | 僅允許草稿或尚未產生影響的資料；正式資料需用作廢或反向事件。 |
| 修改 | `update` | 修改主檔、草稿、偏好設定、單據狀態、應收應付狀態。 |
| 查詢 | `read` | 查看模組、搜尋、篩選、開啟詳情、包含作廢查詢。 |
| 列印 | `print` | 列印報表、單據、庫存表、應收應付清單、稽核紀錄。 |
| 匯出 | `export` | CSV、JSON 備份、報表匯出、稽核資料匯出。 |
| 還原 | `restore` | 備份還原、範例資料重設、資料遷移。 |
| 權限 | `access` | 角色切換、權限拒絕、敏感欄位遮罩、越權嘗試。 |

## 必要欄位

每筆稽核事件至少包含：

| 欄位 | 說明 |
|---|---|
| `auditId` | 稽核事件唯一編號。 |
| `occurredAt` | 發生時間，ISO 字串。 |
| `actorId` | 操作者 ID；單機版可先用 `local-user`。 |
| `actorName` | 操作者顯示名稱。 |
| `roleAtOperation` | 操作當下角色。 |
| `action` | `create`、`delete`、`update`、`read`、`print`、`export`、`restore`、`access`。 |
| `entityType` | 資料類型，例如 `product`、`purchase`、`sale`、`payment`、`report`。 |
| `entityId` | 資料 ID。 |
| `documentNo` | 單據編號，沒有單號則留空。 |
| `sourceDocumentNo` | 來源單號。 |
| `relatedDocumentNos` | 關聯單號清單。 |
| `summary` | 人可讀的操作摘要。 |
| `reason` | 操作原因；作廢、還原、刪除、修改已確認資料時必填。 |
| `before` | 修改前摘要或差異欄位。 |
| `after` | 修改後摘要或差異欄位。 |
| `result` | `success`、`denied`、`failed`。 |
| `riskLevel` | `low`、`medium`、`high`。 |

守門標記：`audit-trail-required-fields`

## 新增

新增紀錄需能回答：

- 誰建立。
- 建立什麼資料。
- 來源是否來自草稿、退貨、反向事件或備份還原。
- 是否立即影響庫存、財務、業績或報表。

第一版需記錄：

- 商品、分類、倉庫、往來對象新增。
- 採購、銷售、盤點、調撥、退貨新增。
- 應收、應付、收付款新增。
- 備份還原後由系統產生的資料遷移事件。

守門標記：`audit-create-traceable`

## 刪除

刪除分成三種：

| 類型 | 規則 |
|---|---|
| 草稿刪除 | 可刪，但要保留 `deletedAt`、`deletedBy`、`deleteReason` 與稽核事件。 |
| 正式資料刪除 | 不可直接刪除，需作廢或建立反向事件。 |
| 主檔停用 | 不是真刪除，需記錄停用原因與操作者。 |

已確認、已付款、已影響庫存、已出現在報表或已被關聯的資料，不允許硬刪。

守門標記：`audit-delete-tombstone`

## 修改

修改需依風險拆層：

| 類型 | 規則 |
|---|---|
| 主檔修改 | 記錄欄位差異，例如名稱、分類、成本、售價、啟用狀態。 |
| 草稿修改 | 記錄修改者與修改時間，可只保留摘要。 |
| 已確認單據修改 | 需申請、核准或以差額事件處理，不直接覆寫。 |
| 成本修改 | 高風險，需記錄修改前後成本與理由。 |
| 權限或偏好修改 | 記錄設定差異與操作者。 |

修改稽核不可只記「已修改」，需至少知道哪些欄位變了。

守門標記：`audit-update-diff`

## 查詢

查詢紀錄需兼顧可追溯與避免過度噪音：

| 查詢行為 | 記錄方式 |
|---|---|
| 切換模組 | 記錄 `read`，風險低。 |
| 搜尋單號、客戶、供應商 | 記錄 query 摘要，避免記錄敏感全文。 |
| 開啟作廢、沖銷、財務、毛利資料 | 記錄 `read`，風險中。 |
| 包含作廢查詢 | 記錄 `read`，需帶 `includeVoided=true`。 |
| 權限拒絕 | 記錄 `access denied`，風險中或高。 |

第一版可以只記高風險查詢與權限拒絕；多人版需補足敏感查詢與稽核報表查閱紀錄。

守門標記：`audit-read-sensitive-query`

## 列印

列印視同資料輸出，需記錄：

- 列印者。
- 列印時間。
- 列印內容類型：報表、庫存、採購、銷售、財務、稽核紀錄。
- 篩選條件，例如月份、倉庫、包含作廢。
- 是否含成本、毛利、應收、應付等敏感欄位。
- 列印版次或報表產生時間。

UI 第一版若瀏覽器列印事件無法完整攔截，至少在使用系統內「列印」按鈕時建立稽核事件。

守門標記：`audit-print-traceable`

## 稽核查詢 UI

稽核角色需要一個獨立查詢入口，第一版可放在報表或未來獨立模組。

至少需支援：

- 依時間區間查詢。
- 依操作者、角色查詢。
- 依 action 查詢。
- 依單據編號查詢。
- 依資料類型查詢。
- 只看高風險事件。
- 匯出稽核紀錄。

UI 顯示欄位：

| 欄位 | 說明 |
|---|---|
| 時間 | `occurredAt`。 |
| 操作者 | `actorName` 與 `roleAtOperation`。 |
| 動作 | 新增、刪除、修改、查詢、列印、匯出、還原、權限拒絕。 |
| 對象 | `entityType`、`entityId`、`documentNo`。 |
| 摘要 | 人可讀說明。 |
| 結果 | 成功、拒絕、失敗。 |
| 風險 | 低、中、高。 |

守門標記：`audit-ui-search-export`

## 資料保存與備份

- 稽核紀錄需納入完整 JSON 備份。
- 還原備份時不得遺失稽核紀錄。
- 還原本身也需新增一筆 `restore` 稽核事件。
- 稽核紀錄不可因重設範例資料而靜默消失；若第一版必須重設，需在 UI 明確警示。
- 多人版需加入保留年限、封存、不可竄改儲存與服務端時間。

守門標記：`audit-backup-retention`

## 與其他基準線的關係

- 權限控管基準線決定誰能做，稽核軌跡記錄誰做了或被拒絕。
- 審核流程基準線決定送審、核准、退回與確認的狀態，稽核軌跡記錄每次狀態轉換。
- 資料生命週期與作廢基準線決定不可直接刪除與反向事件，稽核軌跡保存操作鏈。
- 作廢反向事件 UI 基準線顯示原單與沖銷單，稽核軌跡保存建立與查詢紀錄。
- 雲端同步基準線導入後，稽核寫入需移到服務端。

## 第一階段實作邊界

第一階段不追求完整法遵級不可竄改，但需先建立資料形狀與 UI 位置：

- 新增 `auditLogs` 資料集合。
- 建立 `recordAuditEvent(action, payload)`。
- 先記錄高風險寫入：新增、修改、作廢、沖銷、退貨、收付款、備份還原、重設範例資料。
- 先記錄權限拒絕與敏感查詢。
- 列印先從系統內報表列印按鈕開始。
- 備份匯出需包含 `auditLogs`。

後續再補：

- 所有一般查詢事件。
- 稽核紀錄雜訊抑制。
- 雜湊鏈或簽章。
- 服務端不可竄改儲存。
