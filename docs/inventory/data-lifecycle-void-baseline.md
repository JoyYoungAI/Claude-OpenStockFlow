# 資料生命週期與作廢基準線

本基準線定義 StockFlow 單據資料從建立、確認、修改、作廢到反向處理的共同規則。它補上「單據不能只是刪掉」的商業邏輯，確保庫存、財務、業績、報表與備份還原都能追溯原始紀錄。

## 核心原則

- `documentNo` 是單據生命週期與跨模組關聯的主鍵。
- 已影響庫存、財務、業績或報表的單據，不可直接刪除。
- 作廢不改寫歷史；需要抵銷影響時，建立反向事件或沖銷單據。
- 報表預設排除作廢單，但必須能查詢作廢紀錄與原因。
- 備份還原後，生命週期狀態、作廢資訊、反向事件與單據關聯都必須保留。

## 單據狀態

| 狀態 | 系統值 | 說明 |
|---|---|---|
| 草稿 | `draft` | 尚未確認，不應影響庫存、財務、業績或正式報表。 |
| 已確認 | `confirmed` | 已正式成立，並已依單據類型產生庫存、財務或業績影響。 |
| 已修改 | `amended` | 已確認單據後續被允許修正，需保留修改紀錄與原因。 |
| 已作廢 | `voided` | 原單保留，但不再作為有效交易；若已產生影響，需透過反向事件抵銷。 |
| 已沖銷/已反向處理 | `reversed` | 原單或其影響已由反向事件抵銷，需能追溯原單與反向單據。 |

狀態應由明確操作轉換，不應以刪除資料、清空欄位或覆寫明細來代表作廢。

## 不直接刪單據

下列資料只要已經被確認或被報表引用，就不得直接刪除：

- 採購進貨 `PO`
- 銷售出貨 `SO`
- 盤點調整 `ADJ`
- 調撥 `TRF`
- 借出 `LOAN`
- 借出歸還 `LRTN`
- 收款 `RCPT`
- 付款 `PAY`

允許刪除的範圍只限於尚未確認、尚未產生影響、尚未被報表引用的草稿資料。UI 應以「作廢」或「建立反向事件」取代危險的刪除語意。

## 作廢規則

作廢單據至少要保留下列欄位：

| 欄位 | 說明 |
|---|---|
| `status` | 設為 `voided` 或在反向完成後設為 `reversed`。 |
| `voidReason` | 作廢原因，必填。 |
| `voidedAt` | 作廢時間。 |
| `voidedBy` | 執行作廢的操作者欄位。 |
| `sourceDocumentNo` | 反向事件指向的原始單據編號。 |
| `reversalDocumentNo` | 抵銷原單影響的反向單據編號。 |
| `relatedDocumentNos` | 與原單、收付款、借出歸還、調撥或報表相關的單據清單。 |

若單據已造成庫存或金流影響，作廢時不得直接改回原資料，必須建立反向事件：

- 已進貨的 `PO`：建立反向庫存與應付沖銷。
- 已出貨的 `SO`：建立反向庫存、應收沖銷與業績沖銷。
- 已調整的 `ADJ`：建立相反數量的調整事件。
- 已調撥的 `TRF`：建立反向調撥事件。
- 已借出的 `LOAN`：依現況建立借出取消、轉銷售或歸還流程，不可直接回可售庫存。
- 已歸還的 `LRTN`：若仍在待驗區，依待驗流程處理；若已入可售庫存，需建立反向庫存事件。
- 已收款的 `RCPT`、已付款的 `PAY`：建立反向收付款事件，不直接刪除金流紀錄。

## 修改規則

已確認單據若允許修改，需符合下列規則：

- 修改後狀態為 `amended` 或保留 `confirmed` 並建立修改紀錄。
- 需記錄 `amendedAt`、`amendedBy`、`amendReason`。
- 若修改會影響庫存、財務或業績，應以差額事件處理，不直接覆寫原影響。
- 報表要能看出目前有效數字，也要能追溯原始單據與修改紀錄。

## 報表引用

報表預設採用有效交易資料：

- 預設排除 `voided` 單據。
- 預設採用反向處理後的淨影響。
- 可切換查詢作廢紀錄、作廢原因、作廢時間與操作者。
- 歷史報表必須能顯示原單與反向事件的關聯，例如 `sourceDocumentNo` 與 `reversalDocumentNo`。
- 若單據已作廢但沒有完成反向處理，報表需標示風險狀態，不可靜默當作有效或無效。

## 備份還原

備份與還原需保留完整生命週期資訊：

- 單據狀態：`draft`、`confirmed`、`amended`、`voided`、`reversed`。
- 作廢資訊：`voidReason`、`voidedAt`、`voidedBy`。
- 修改資訊：`amendedAt`、`amendedBy`、`amendReason`。
- 關聯資訊：`documentNo`、`sourceDocumentNo`、`reversalDocumentNo`、`relatedDocumentNos`。
- 庫存、財務、業績的反向事件。

還原後不得只留下有效單據而遺失作廢與沖銷紀錄，否則會讓報表、庫存與帳款失去稽核基礎。

## 第一版 UI 範圍

第一版只放最小可見提示，避免一次改太大：

- 單據列表顯示狀態標籤。
- 作廢操作需要填寫原因。
- 對已確認且已影響庫存、財務、業績或報表的單據，顯示不可直接刪除提示。
- 危險操作使用既有危險按鈕樣式，disabled 時保持可見並以提示說明原因。
- 報表篩選保留日後加入「包含作廢單」的空間。

## 守門檢查

`scripts/check.ps1` 應守住：

- 本規格檔存在，且主規格索引連結到本規格。
- 規格包含 `draft`、`confirmed`、`amended`、`voided`、`reversed` 五種狀態。
- 規格包含 `voidReason`、`voidedAt`、`voidedBy`、`sourceDocumentNo`、`reversalDocumentNo`、`relatedDocumentNos`。
- 規格明確說明已影響庫存、財務、業績或報表的單據不可直接刪除。
- 規格明確說明報表預設排除作廢單，且備份還原需保留生命週期與關聯資料。

守門標記：

- `no-direct-delete-confirmed-documents`
- `reports-exclude-voided-by-default`
- `backup-restore-retains-lifecycle-links`
