# 作廢反向事件 UI 基準線

本基準線定義作廢後畫面要呈現什麼，以及反向事件如何建立、查詢與追溯。現階段已做到最小作廢保留紀錄，下一階段需讓使用者清楚看見原單、作廢、反向事件與報表影響。

## 核心原則

- 作廢不是刪除。
- 已造成庫存、財務或業績影響的單據，需顯示是否已有反向事件。
- 使用者要能從原單看到反向單，也能從反向單回到原單。
- 作廢原因、時間、操作者必須可見。
- 報表預設排除作廢單，但查詢時可包含作廢與反向事件。

## UI 元素

| 元素 | 說明 |
|---|---|
| 狀態標籤 | 顯示草稿、已確認、已作廢、已沖銷。 |
| 作廢原因 | 顯示原因、操作者、時間。 |
| 關聯單據區 | 顯示 `sourceDocumentNo`、`reversalDocumentNo`、`relatedDocumentNos`。 |
| 反向事件提示 | 顯示是否已建立反向庫存、帳款或業績事件。 |
| 包含作廢切換 | 報表與查詢可切換包含作廢單。 |
| 建立反向事件按鈕 | 僅有權限者可操作，無權限時 disabled 並說明原因。 |

## 作廢後可見資訊

列表與詳情至少需顯示：

- 原單號。
- 單據狀態。
- 作廢原因。
- 作廢時間。
- 作廢操作者。
- 是否已沖銷。
- 反向單據編號。
- 對庫存、應收應付、毛利或業績的影響。

## 反向事件建立

不同單據需建立不同反向事件：

| 原單 | 反向處理 |
|---|---|
| `PO` | 反向進貨庫存、應付沖銷。 |
| `SO` | 回補庫存、應收沖銷、業績沖銷。 |
| `ADJ` | 建立相反數量調整。 |
| `TRF` | 建立反向調撥。 |
| `RCPT` | 建立反向收款。 |
| `PAY` | 建立反向付款。 |
| `LOAN` / `LRTN` | 依借出、歸還、待驗狀態建立對應反向流程。 |

## 報表與查詢

- 預設顯示有效資料。
- 可開啟「包含作廢」查詢。
- 可開啟「只看作廢 / 只看反向事件」查詢。
- 庫存異動需顯示反向事件方向。
- 財務報表需顯示沖銷後淨額與原始金額。

## 第一階段實作邊界

已完成的最小版：

- 作廢保留原單。
- 顯示作廢狀態與原因。
- 報表預設排除作廢。
- 應收應付不可再沖作廢帳款。

下一階段：

- 增加包含作廢查詢。
- 增加原單與反向單連結。
- 增加反向事件建立入口。
- 增加作廢詳情面板。
