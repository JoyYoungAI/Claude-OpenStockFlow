# 基本資料規格

基本資料是出貨單成立前的第一層前置條件。使用者需要先有分類、倉庫與往來對象，後續商品、進貨、銷售與財務才有穩定基準。

## 範圍

- 產品類別主檔。
- 倉庫主檔。
- 往來對象主檔。
- 完整 JSON 備份匯出。
- 備份檔檢查、預覽與整包還原。

## ProductCategory

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---:|---|
| id | number | 是 | 類別 ID |
| code | string | 是 | 類別代碼，不可重複 |
| name | string | 是 | 類別名稱，不可重複 |
| sortOrder | number | 是 | 顯示排序 |
| note | string | 否 | 備註 |
| active | boolean | 是 | 是否啟用 |

## Warehouse

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---:|---|
| id | number | 是 | 倉庫 ID |
| code | string | 是 | 倉庫代碼，不可重複 |
| name | string | 是 | 倉庫名稱，不可重複 |
| type | string | 是 | 類型，例如 倉庫、門市、展示、退貨區 |
| note | string | 否 | 備註 |
| active | boolean | 是 | 是否啟用 |

## 資料規則

- 產品類別代碼和名稱必須唯一。
- 倉庫代碼和名稱必須唯一。
- 採購、銷售、盤點必須指定有效且啟用的倉庫。
- localStorage 舊資料格式載入時必須補齊缺少的集合，例如 `partners`、`productCategories`、`warehouses`、`adjustments`。
- 舊資料缺少倉庫資料時，系統必須自動建立預設主倉。
- 舊進貨、銷售、盤點資料缺少 `warehouseId` 時，系統必須自動補到預設主倉。
- 還原備份前必須先檢查商品 SKU 是否重複，以及交易資料是否指向存在的商品。

## 驗證

- 類別新增、重複檢查與停用。
- 倉庫新增、重複檢查與停用。
- 倉庫篩選。
- 備份匯出。
- 備份檢查、預覽與還原。
