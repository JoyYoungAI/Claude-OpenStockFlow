# 操作狀態與風險基準線

進銷存牽涉庫存、單據與金額。使用者若誤以為有庫存而建立出貨單，可能連帶影響倉庫、財務與客戶。因此，操作狀態必須讓新人能快速判斷「這是主要動作、次要動作、危險動作，還是目前不能做」。

## 按鈕語意

| 類型 | 用途 | 視覺方向 |
|---|---|---|
| 主要動作 | 新增、儲存、建立單據 | 綠色實心 |
| 次要動作 | 重新整理、匯出、編輯、快捷鍵提示 | 白底或淡色，不與主動作競爭 |
| 危險動作 | 停用、作廢、還原、重設 | 紅色語意，hover 與 focus 延續危險語意 |
| 目前模組 | 主導覽目前所在頁 | 淡綠底、深綠字、明確邊框，不使用主動作實心樣式 |
| 不可操作 | 條件不足、舊資料、缺少必要主檔 | 保留可見但 disabled，並用 `title` 說明原因 |

## Hover 與焦點

- 可點擊元素 hover 時應有明確狀態變化。
- 鍵盤 focus 必須可見，不能只依賴滑鼠 hover。
- 危險動作的 focus ring 應保持危險語意，避免使用者誤判為一般主要動作。
- disabled 元件不應觸發 hover 的積極樣式。

## Disabled 不是消失

條件不足的按鈕仍應顯示，因為它能告訴使用者系統有這個流程，只是目前缺資料或狀態不允許。

常見 disabled 原因：

- 尚未有啟用商品。
- 尚未有啟用倉庫。
- 尚未選擇付款目標。
- 其他瀏覽器視窗已更新同一份本機資料，目前畫面資料可能過舊。

disabled 按鈕必須透過 `title` 或相鄰狀態提示說明原因。

## 多視窗與本機資料風險

因為第一版是瀏覽器本機版本，使用者可能同時開啟多個視窗、分頁或無痕視窗。若其中一個視窗已更新 `localStorage`，另一個舊畫面不能繼續寫入資料。

風險防護：

- 偵測到同一份本機資料被其他視窗更新時，顯示警示狀態。
- 會寫入資料的操作必須暫停。
- 使用者需先重新整理，讓畫面與本機資料重新對齊。

## 關鍵警示

以下操作必須顯示確認警示：

- 停用商品、分類、倉庫或往來對象。
- 刪除或作廢進貨、銷售、盤點、調撥、付款紀錄。
- 還原備份。
- 重設範例資料。

警示文字應直接說明影響，不只寫「確定嗎」。

## 驗證

`scripts/check.ps1` 必須檢查：

- CSS 存在 `.button-danger`、`.button-secondary`、`.text-button.action-danger`、`:focus-visible`、`.status.is-warning`。
- JS 存在 `bindStorageFreshnessGuard`、`renderActionAvailability`、`setDisabledReason`、`canWrite`。
