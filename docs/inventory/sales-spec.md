# 銷售出貨規格

銷售出貨是風險最高的第一版流程之一，因為它會同時影響庫存、收入、毛利，未來也可能連動應收帳款。系統必須在建立出貨前確認指定倉庫庫存足夠。

## 流程

1. 使用者選擇商品。
2. 選擇出貨倉庫。
3. 填入銷售數量、銷售單價、客戶、日期、備註。
4. 系統檢查該商品在指定倉庫的庫存是否足夠。
5. 系統建立銷售紀錄。
6. 系統扣減該商品在指定倉庫的庫存。
7. 系統計算銷售金額與粗略毛利。

## Sale

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---:|---|
| id | number | 是 | 銷售紀錄 ID |
| productId | number | 是 | 商品 ID |
| warehouseId | number | 是 | 出貨倉庫 ID |
| quantity | number | 是 | 銷售數量 |
| unitPrice | number | 是 | 銷售單價 |
| customer | string | 否 | 客戶 |
| date | string | 是 | 日期，格式 `YYYY-MM-DD` |
| note | string | 否 | 備註 |
| ownerEmployeeId | number | 否 | 銷售單主要負責人，若尚未指定可留空。 |
| ownerDepartmentId | number | 否 | 銷售單負責部門，若尚未指定可留空。 |
| createdByEmployeeId | number | 否 | 建立銷售單的人員 ID，保留給人員權限與稽核使用。 |
| lastEditedByEmployeeId | number | 否 | 最近修改銷售單的人員 ID，保留給後續修改流程使用。 |

## 資料規則

- 銷售數量必須大於 0。
- 銷售必須指定有效且啟用的商品。
- 銷售必須指定有效且啟用的倉庫。
- 銷售數量不可超過指定倉庫的目前庫存。
- 停用商品不可新增銷售，但仍可出現在歷史紀錄和報表中。
- 若目前已選擇本機人員，新增銷售單時需帶入負責人與負責部門，供主管範圍與稽核判斷使用。

## 計算規則

```text
銷售收入 = 銷售數量 * 銷售單價
```

第一版使用商品目前成本估算：

```text
粗略毛利 = 銷售收入 - (銷售數量 * 商品成本)
```

## 驗證

- 銷售新增成功。
- 銷售扣減指定倉庫庫存。
- 庫存不足禁止銷售。
- 銷售資料出現在庫存異動明細。
- 銷售收入與粗略毛利計算正確。
