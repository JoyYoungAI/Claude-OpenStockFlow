# StockFlow work log - 2026-05-31

## v1.17.0 formal operations baseline

Completed:
- Split and aligned the inventory system specification index with module-level and shared baseline specs under `docs/inventory/`.
- Added the missing transfer spec and aligned the finance spec into the inventory spec hierarchy.
- Added formal operations baselines for access control, approval workflow, return flow, costing method, void reversal UI, accounting/tax boundary, and cloud sync.
- Pinned app and asset versions to `1.17.0`.
- Kept the browser-only architecture and continued using localStorage as the single-machine data store.

## Implemented features

Access control:
- Added local role mode without real login.
- Added `canPerform(action, context)` and action permission guards.
- High-risk actions now respect local roles, including backup restore, reset sample data, payments, stock adjustment, voiding, and master data changes.

Approval workflow:
- Added draft save for purchase and sale documents.
- Added document transitions: draft, submitted, approved, rejected, confirmed, and voidRequested.
- Draft/submitted/approved/rejected documents do not affect stock, finance, or reports until confirmed.
- Rejections keep reason and audit fields.
- Void requests keep the document active until formal void handling.

Return flow:
- Added sales returns with `SRTN` document numbers.
- Added purchase returns with `PRTN` document numbers.
- Returns preserve `sourceDocumentNo` and source line references.
- Return quantity cannot exceed the remaining returnable source quantity.
- Sales returns restore stock and reduce receivables.
- Purchase returns reduce stock and reduce payables.
- Stock movements and report totals include return impact.

Costing:
- Added first-stage `standardCost` traceability.
- Sales lines now retain `costBasis` snapshots captured at sale/confirmation time.
- Gross profit reports use historical sales cost snapshots instead of recalculating old sales with the latest product cost.
- Purchase confirmations create `costLayers` skeleton records for future FIFO and moving average work.
- Sales returns reuse the original sales cost basis when reversing gross profit.

## Data and storage

Backup and restore:

## Current readiness

The system is now stronger than a simple starter inventory tracker:
- Basic buying, selling, stock, transfer, finance, backup, reporting, role guards, approval, returns, and simplified cost traceability are present.
- It is suitable for a small single-machine trading company pilot, with operational caution.

Still not complete formal ERP/accounting:
- No real login or server-side permissions yet.
- No multi-user cloud database yet.
- No formal invoice, tax filing, or balanced accounting ledger yet.
- FIFO and moving average are prepared by data structure but not fully executed as costing methods yet.
- Void reversal UI is still minimal.
