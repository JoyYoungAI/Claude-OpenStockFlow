## v1.17.0

Completed:
- `v1.17.0`: Pinned the formal operations foundation milestone. Added minimum local role mode, `canPerform(action, context)`, role-based disabled reasons, guarded high-risk actions such as void, backup restore, reset, payments, stock adjustment, and master data changes, and kept access-control text under `inventoryI18n.js`.
- `v1.17.0`: Added the first minimal approval workflow implementation for purchase and sale documents: save as draft, submit, approve, reject, confirm, and request void. Draft/submitted/approved/rejected documents do not affect stock or finance until confirmed, while void requests keep the original document active until the owner voids it.
- `v1.17.0`: Added the first minimal return flow implementation. Sales returns create `SRTN` records, restore stock, reduce receivables, and appear in stock movements; purchase returns create `PRTN` records, reduce stock, reduce payables, and preserve source document links. Data schema is now `9` to retain return records in backup and restore.
- `v1.17.0`: Added the first minimal costing implementation. Sales lines now retain a `standardCost` cost snapshot through `costBasis`, purchase confirmations create `costLayers` skeleton records, and gross profit reports use historical sales cost snapshots instead of silently recalculating old sales with the latest product cost.
